**Problem**: Whoever reads the weekly numbers needs to know which metrics moved and why; when a model finds the cause and writes the review, is the cause right, and does every number trace back to a query result? (tested on synthetic data).

**What I did**: On synthetic local-services group-buying data I built a metric dictionary, a one-query weekly monitor, contribution and rate-mix breakdowns and number-checked weekly reviews, and compared three ways of finding the cause: a fixed-rule script, a one-prompt approach and an agent; the known-answer test cases and the evaluation plan were frozen before the run; the same flow was also built as a Dify workflow.

**Results**: 

- All planted causes right: script 31/36, one prompt 28/36, agent 34/36
- Case by case the agent beat the one prompt 6 to 0 (p = 0.031); against the script it is too close to call (p = 0.45)
- Released after at most one revision: one prompt 35/36, agent 33/36; every review held back failed on Chinese number words, none on a wrong number

## Summary

On synthetic local-services group-buying data, "weekly monitor → breakdown by dimension → weekly review → number check" runs as one repeatable line, and three ways of finding the cause are compared: a fixed-rule script, a one-prompt approach that hands the model a fixed pack of query results, and an agent that queries with tools. Every paragraph with a number must cite the query-result row it comes from and is checked with evidence-check; a review that fails goes back for one revision and is held back if it fails again. The data is generated by script from random seeds and is not any platform's real business data.

- **Place in the portfolio**: Scenario: judgement
- **Link to the core component**: The review's number check calls the evidence-check 0.4.0 script directly, with three project rules on top.
- **Models used**: Both model approaches in the evaluation use claude-haiku-5-5 (effort medium, Message Batches API); the script makes no model calls. The Dify version's model nodes default to gpt-5-mini from the platform's allowance and only show the flow runs there; they are not in the evaluation.

## Uses

- A weekly anomaly review for a business analytics team: findings, causes and next steps, with every number traceable to a query result.
- A pre-launch check: compare ways of finding the cause on data with planted answers, for accuracy and cost.

## Out of scope

- The data is synthetic, not any platform's real business data; metric definitions were written for this data.
- Recommended actions are not scored.
- The Dify version only shows the flow runs; it is not evaluated.

## Grader calibration

- No grader is used: causes are scored by rule against the answers planted when the cases were made, and release is decided by the evidence-check 0.4.0 script plus three structural rules.

## Limitations and failure cases

- The data, the planted events, the monitor and all three approaches come from the same project; the events are clean and sit inside existing dimensions, which real causes often do not.
  - Recommendation: Before real data, build cases from past weeks whose causes are already known and test again.
- The agent and the script differ by a few cases (p = 0.45); these cases cannot separate them.
  - Recommendation: Separating them needs more cases, especially two-cause and two-dimension ones.
- The number check is too strict on Chinese number words: the reviews held back in the end had no wrong number, and their failing paragraphs failed on words like 这两项 ("these two") or 前一天 ("the day before").
  - Recommendation: Treat counting words apart from quantities, or give them their own rule; how strict to be is a product decision to make with the people who use it.
- The agent's first drafts had 19 paragraphs quoting a number not in the cited row, all fixed only by the one revision; without the check they would have gone out.
  - Recommendation: Keep the check before anything goes out.
- Recommended actions are not scored.
  - Recommendation: Write scoring rules for the actions and test them on the same cases.
